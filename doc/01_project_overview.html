1. 文書目的

本書は、レシート画像をGemini APIで解析し、利用者が内容を確認した後にPostgreSQLへ保存するWebアプリケーションの全体像を示す納品資料です。記載内容は、納品ZIP内の現行ソースコード・設定・テストコードを正として整理しています。

2. システム概要

利用者ブラウザから画像/ZIPとGemini APIキーを入力
GitHub PagesHTML / CSS / JavaScriptの静的フロント
Render Web ServiceJava 21 / Spring Boot REST API
Gemini APIOCR相当の文字抽出＋構造化
PostgreSQL原文行・ハッシュ・構造化データを保存

3. 主な提供機能

  • JPEG / PNGの単一画像、またはJPEG / PNGを含むZIPの読み込み
  • Gemini APIキーの画面入力とリクエスト単位利用
  • レシート印字文字の行単位抽出
  • 店舗・購入日時・合計金額・商品等の構造化データ生成
  • 画像SHA-256による保存済みレシートの重複防止
  • 解析とPostgreSQL保存の操作分離
  • 保存済みレシート一覧・詳細表示
  • 選択した保存済みレシートの削除
  • Render向けヘルスチェック

4. 納品物

区分格納先内容

APIreBack/Spring Bootバックエンド、Dockerfile、Render Blueprint

5. 納品時点の重要事項

  • フロントエンドのファイル入力は1個です。直接画像は1枚、ZIPの場合は内部画像を順次展開して処理します。現行コードにはZIP内画像枚数の固定上限はありません。
  • 各画像はバックエンドで5MB以下のJPEG / PNGに限定されます。
  • Gemini APIキーは環境変数へ保持せず、画面入力値をその解析リクエストにだけ使用します。
  • 保存済み画像と同一SHA-256の再解析は409で拒否されます。
  • 認証・ユーザー管理は実装していません。access-guard.js はメニュー経由の画面遷移を促すUI制御であり、認証機構ではありません。
