1. ディレクトリ責務

パスルール
reFront/ブラウザだけで実行できる静的資産
reBack/Java/Spring Boot、Docker/Render設定
doc/納品HTML。ソース仕様変更時に同時更新

2. Frontendルール

  • 外部フレームワーク追加前にVanilla JSでの必要性を検討
  • API URLはconfig.jsへ集約
  • APIキーをlocalStorage/sessionStorageへ書かない
  • ユーザー表示文字列はtextContentで挿入し、解析文字列をinnerHTMLへ入れない
  • 長時間通信はAbortControllerでtimeoutを設ける
  • ZIP処理変更時は破損・暗号化・ディレクトリ・非画像ケースをテストする

3. Backendルール

  • ControllerはHTTP入出力、Serviceはユースケース、RepositoryはDB処理へ責務分離
  • 動的SQL識別子はReceiptTableNameの安全性検証を必須とする
  • 値はPreparedStatement / JdbcTemplate parameter bindingを使う
  • ReceiptExceptionはHTTP status・code・user messageを明示
  • 秘密値をログへ出さない
  • Gemini応答は外部入力として再検証する

4. 変更時チェック

  1. 要件・設計・API・DB文書の影響確認
  2. Frontend smoke test更新
  3. Backend unit/integration test更新
  4. 環境変数追加時は22_environment_variables.htmlとrender.ymlを更新
  5. DB変更時は削除・移行・後方互換性を確認
  6. テスト結果を27_test_result_report.htmlへ反映
