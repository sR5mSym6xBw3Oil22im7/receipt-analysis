2. 解析シーケンス

  1. Controllerがmultipartのfile/geminiApiKeyを受領
  2. Validatorで空・サイズ・MIMEを検証
  3. MultipartFileをbyte[]へ読み込み
  4. SHA-256を算出
  5. GeminiReceiptAnalyzerがAPIキー検証→Gemini呼び出し
  6. linesをtrim・空行除去・最大1000行へ正規化
  7. Repositoryがimage hashを予約
  8. lines / sha256 / structuredDataを返却

3. 保存シーケンス

  1. JSONのlines / sha256 / structuredDataを受領
  2. null lineを除去し空を拒否
  3. sha256を64桁hexとして検証・小文字化
  4. registryの未保存予約行をUPDATEし、新しい安全なテーブル名を割当
  5. 動的原文テーブルをCREATEし、line_no順にbatch INSERT
  6. structured summary/itemテーブルを必要に応じCREATEし、構造化結果をINSERT
  7. tableName / lineCount / lines / sha256を返却

4. トランザクション

ReceiptService.store と ReceiptTableRepository.deleteReceipt はトランザクション対象です。保存処理ではハッシュ紐付け・動的テーブル作成・構造化データ保存を、削除処理では原文・サマリ・商品明細・ハッシュ削除を同一ユースケースとして扱います。

5. 一覧・詳細

information_schema.tables から receipt_% を検索した後、ReceiptTableName.isSafe で実レシート用テーブルだけに絞り込みます。管理テーブルは一覧対象になりません。
