1. 目的

Geminiへレシート画像を渡し、表示用の原文行と将来の検索・集計に利用できる構造化データを同じ応答で取得します。

2. モデルとSDK

項目設定
モデルgemini-3.5-flash-lite
Java SDKcom.google.genai:google-genai:1.67.0
Gemini timeout180,000 ms
candidateCount1
responseMimeTypeapplication/json
出力制御SDK SchemaによるStructured Output

3. 原文抽出ルール

  • 印字文字を上から下へ読み、1行ごとにlinesへ格納
  • 推測で存在しない文字を追加しない
  • バーコード画像そのものは文字列化しなくてよい
  • Backendでnull除外、trim、空行除外、最大1000行に正規化
  • 正規化後0行なら422 NO_TEXT_FOUND

4. structuredData

項目型ルール
storeNamestring/null店舗名
branchNamestring/null支店名
storeCategorystring/nullスーパー/コンビニ/ドラッグストア/飲食店/その他
purchasedAtISO local datetime string/nullJava LocalDateTimeへparse。失敗時null
totalAmountinteger/null合計金額
paymentMethodstring/null支払方法
receiptNumberstring/null番号
itemsarray購入商品・サービス。税/小計/合計/預り/釣銭は除外

5. 商品項目

項目型備考
namestring空/blankはDB保存時に除外
categorystring食料品/日用品/飲食/交通・移動/その他。null時DB保存は「その他」
quantitynumber/nullBigDecimal
unitPriceinteger/nullLong
amountinteger/nullLong

6. APIキー処理

  • 画面入力値をmultipartでBackendへ送る
  • trimし、空と512文字超を拒否
  • Gemini ClientはそのリクエストのactiveApiKeyで生成しtry-with-resourcesで閉じる
  • レスポンス、DB、Browser StorageへAPIキーを保存しない
  • 429/RESOURCE_EXHAUSTEDをGEMINI_QUOTA_EXCEEDEDへ変換
  • 401/403/API-key関連拒否をGEMINI_API_KEY_REJECTEDへ変換

7. AI品質上の注意

AI解析はOCR専用エンジンの決定論的結果ではなく、画像品質・印字状態・モデル挙動により誤読・欠落があり得ます。UIは保存前に原文行を確認できる設計ですが、構造化データは現行UIでは表示・編集しません。
