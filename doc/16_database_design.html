1. データモデル概要

receipt_image_hash_registry
image_sha256 PK / table_name UNIQUE nullable
↓ 保存時にtable_nameを割当
receipt_<uuid32>
レシートごとの原文行
↓ 同一table_nameを論理キーとして利用
receipt_structured_summary 1 ── N receipt_structured_item

2. receipt_image_hash_registry

列型制約用途
image_sha256VARCHAR(64)PRIMARY KEY画像バイト列SHA-256
table_nameVARCHAR(64)UNIQUE / NULL可未保存予約時NULL、保存時receipt_<uuid>
created_atTIMESTAMPTZNOT NULL DEFAULT CURRENT_TIMESTAMP予約作成日時

3. 動的原文テーブル receipt_<uuid32>

列型制約用途
idBIGINTIDENTITY PRIMARY KEY内部ID
line_noINTEGERNOT NULL原文行番号（1始まり）
textTEXTNOT NULLGemini抽出行
created_atTIMESTAMPTZNOT NULL DEFAULT CURRENT_TIMESTAMP保存日時
テーブル名はBackend生成UUIDのみを使用し、正規表現 receipt_[0-9a-f]{32} に一致する場合だけSQL識別子として利用します。

4. receipt_structured_summary

列型制約／用途
idBIGINTIDENTITY PK
receipt_table_nameVARCHAR(64)NOT NULL UNIQUE / 原文テーブルの論理参照
image_sha256VARCHAR(64)NOT NULL UNIQUE
store_nameVARCHAR(255)店舗名
branch_nameVARCHAR(255)支店名
store_categoryVARCHAR(50)店舗カテゴリ
purchased_atTIMESTAMP購入日時
total_amountBIGINT合計金額
payment_methodVARCHAR(100)支払方法
receipt_numberVARCHAR(100)レシート番号
created_atTIMESTAMPTZ作成日時

5. receipt_structured_item

列型制約／用途
idBIGINTIDENTITY PK
receipt_table_nameVARCHAR(64)NOT NULL / サマリーテーブルへの外部キー（ON DELETE CASCADE）
item_noINTEGERNOT NULL / table_nameと組合せUNIQUE
item_nameTEXTNOT NULL
categoryVARCHAR(50)NOT NULL
quantityNUMERIC(12,3)数量
unit_priceBIGINT単価
amountBIGINT金額
created_atTIMESTAMPTZ作成日時

6. schema.sql内のadminテーブル

admin(userId, password) の既存テーブル定義は互換性のため残しますが、ログイン機能では使用しません。固定アカウントの更新・挿入SQLは削除済みです。認証情報は ADMIN_USERNAME と ADMIN_PASSWORD_HASH の環境変数からBackendへ設定します。

7. 削除仕様と注意点

削除処理：動的原文テーブル、receipt_structured_summary、receipt_structured_item、receipt_image_hash_registry の関連データを同一トランザクションで削除します。receipt_structured_item.receipt_table_name からサマリーテーブルへの外部キーと ON DELETE CASCADE を設定しています。
