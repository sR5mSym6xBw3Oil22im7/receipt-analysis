1. 引継ぎサマリ

納品時にコードと既存文書・テスト記録を照合し、今後の保守で注意すべき差異と改善候補を整理します。今回のstructured item削除対応を反映した現行状態を基準に記載します。

2. 既知課題

ID重要度内容影響推奨対応
ISS-01解消済みレシート削除時のstructured item削除明示DELETEとFK ON DELETE CASCADEで孤立商品行を防止対応済み（2026-09-19）
ISS-02中ZIPの総サイズ・展開総量・エントリ数に上限なし巨大ZIPでBrowserリソースを消費し得る入力上限と展開上限を実装
ISS-03解消済み管理APIの認証・認可Backendセッション、ADMINロール、CSRFでreceipt APIを保護認証統合テストを継続
ISS-04中構造化データを保存するがUIで表示・編集しないAI誤認識を利用者が確認できない保存前review UI
ISS-05低未保存hash予約行に有効期限なし解析だけで離脱したhashが残る一定期間NULL行を掃除
ISS-06解消済みReferrerベースの画面制御Frontend guardを削除し、Backendで管理画面を保護なし
ISS-07解消済み固定値ログインBackendのBCrypt照合とセッション認証へ移行本番認証環境変数を設定する

3. 旧文書との差異

旧記載現行コード
最大5枚まで直接入力は1ファイル。ZIP内画像数に固定上限なし
重複時にその画像だけskipし後続保存現行app.jsは解析/保存でエラーが発生するとそのループを中断
Spring Boot 3pom.xmlはSpring Boot 4.1.0
原文のみ保存現行ではstructured summary/itemも保存
