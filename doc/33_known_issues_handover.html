33. 既知課題・引継ぎ事項

1. 引継ぎサマリ

納品時にコードと既存文書・テスト記録を照合し、今後の保守で注意すべき差異と改善候補を整理します。これらは本ドキュメント作成時にソースを変更せず、現状を明示したものです。

2. 既知課題

ID重要度内容影響推奨対応
ISS-01高レシート削除時にreceipt_structured_itemを削除しない孤立商品行が残るDELETE追加またはFK ON DELETE CASCADE
ISS-02中ZIPの総サイズ・展開総量・エントリ数に上限なし巨大ZIPでBrowserリソースを消費し得る入力上限と展開上限を実装
ISS-03中認証・認可なし公開APIをアプリ内で利用者制限できない用途に応じ認証/rate limit導入
ISS-04中構造化データを保存するがUIで表示・編集しないAI誤認識を利用者が確認できない保存前review UI
ISS-05低未保存hash予約行に有効期限なし解析だけで離脱したhashが残る一定期間NULL行を掃除
ISS-06低Frontendのdirect-access guardはreferrer依存ブックマーク直アクセスがindexへ戻るUX要件に応じ撤廃/ルーティング見直し

3. 旧文書との差異

旧記載現行コード
最大5枚まで直接入力は1ファイル。ZIP内画像数に固定上限なし
重複時にその画像だけskipし後続保存現行app.jsは解析/保存でエラーが発生するとそのループを中断
Spring Boot 3pom.xmlはSpring Boot 4.1.0
原文のみ保存現行ではstructured summary/itemも保存

4. テスト記録の扱い

test_evidence/ は変更履歴上の過去ログを含み、現行ソースにないendpointや旧UIフローを記述したファイルがあります。今後はファイル名へ日付・commit hashを付ける、またはCI成果物として版管理することを推奨します。

5. リリース前の必須確認

  • Maven利用可能環境でbackend testを再実行
  • 実Gemini APIキーによる画像解析
  • 実Render PostgreSQLへの保存・一覧・削除
  • ISS-01（structured item削除）の扱いをリリース判断で明確化
