1. 目的

解析と保存の分離、画像・APIキー検証、重複管理、DB永続化、画面導線、外部サービス障害時のエラー処理を中心に検証します。

2. テストレベル

レベル対象手段
Frontend smokeHTML/JSの契約・設定Node.js node --test
Backend unitValidator、API key、table name、Gemini error mappingJUnit
Backend repositoryDDL/DML、一覧/詳細、hash削除H2 PostgreSQL mode
Backend integrationController→Service→RepositorySpring Boot Test + MockMvc + stub analyzer
Static reviewrender.yml、application.yml、秘密情報ソース照合
Manual/E2EGitHub Pages→Render→Gemini→PostgreSQL実環境で実キーを使用

3. 合否基準

  • 自動テストは0 fail
  • 解析操作のみでは動的receiptテーブルを作成しない
  • 保存時にだけ原文を永続化する
  • 保存済み同一画像は409になる
  • APIキーを成果物・DB・Browser Storageへ保存しない
  • 主要APIが仕様status/codeを返す
  • 本番公開時はhealth/CORS/解析/保存/参照/削除を確認

4. テストデータ

  • Backend MockMultipartFile: image/jpegの4 bytesダミー（Geminiはstub）
  • H2 in-memory DB（PostgreSQL mode）
  • Frontendはソース文字列／構造契約をNode testで確認
  • 実AI E2Eでは秘密キーをログや成果物へ残さない

5. 制約

今回の納品文書作成環境にはMavenコマンドがないため、Backend JUnitはこの納品作業中に再実行できませんでした。Frontend 17件は2026-09-11に現行ソースで再実行済みです。
